## Full send

Rules for unattended "full send" runs, where an agent proves, files, babysits
and merges its own PRs.

### Commands

Use bun. npm is blocked.

| Step | Command |
| --- | --- |
| Install | `bun install --frozen-lockfile` |
| Typecheck | `bun run typecheck` (runs `next typegen`, then `tsc --noEmit`) |
| Lint | `bun run lint` |
| Test | `bun run test` (`bun test`, 12 files under `tests/`, no network) |
| Build | `bun run build` (prerenders about 3,000 pages, takes about 30 s) |
| Dev server | `bun run dev` |

CI (`.github/workflows/ci.yml`) runs install, typecheck, lint, test and build
in one job named `ci`, on every pull request and on every push to `main`. That
check is required by the `main` ruleset, and the branch must be up to date
with `main` before merging.

### Viewing the app

- `bun run dev` serves the site at http://localhost:3000. If port 3000 is
  taken, Next.js picks the next free port and prints it.
- There is no login, database or seed step. All content comes from the JSON
  files in `data/`, which are committed.
- Useful pages: `/` (search), `/clans/<slug>` (for example
  `/clans/abercromby`), `/names/<name>` (for example `/names/abbot`) and
  `/about`.

### What merging to main does

- The site is hosted on Vercel at https://clans-alpha.vercel.app. Vercel's Git
  integration deploys every push to `main` to production. There is no deploy
  workflow in this repo.
- Mooshay105 has approved this for full send: agents may merge their own PRs
  to `main` once the merge gate passes, even though the merge deploys to
  production. No extra confirmation is needed.
- Merge with a merge commit (`gh pr merge --merge`). That is the only allowed
  method. Branches are deleted on merge.

### Never touch

- Secrets and environment files: `.env*`, `.vercel/`, any Vercel project or
  domain settings, and GitHub repo secrets.
- Repository settings, rulesets and branch protection. Never merge with
  `--admin` or any other bypass.
- `data/clans.json`, `data/names.json` and `data/report.json` by hand. They
  are generated by `bun run pull-data`, which calls Wikipedia, Wikidata and
  GitHub. Do not run it unless the task is to refresh the data. Corrections go
  in `data/overrides.json`, and grouped name spellings go in
  `data/name-variants.json`.
- The licence terms in `data/NOTICE.md` and `LICENCE.md`. Tartan threadcounts
  are CC BY-NC-ND 4.0, so do not add commercial features or remove credits.
- `AGENTS.md` by hand. `next dev` writes its blocks and restores them if they
  are removed, so commit whatever `next dev` adds instead of reverting it.
- Other people's branches and PRs, including Dependabot's, unless the task is
  about them.
